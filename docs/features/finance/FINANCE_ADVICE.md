# 재무 시스템의 데이터 기반 기초판단 · 2026-11-11

사용자 요청: 현금 하회 기준에 따라 CEO 승인 요청·평시 발주 승인 요청·정보 보완을 시스템이 먼저 판단한다. 최종 상신·승인·발주는 기존 사람의 명시적 행동으로 실행한다.

## 판단과 다음 처리

| 입력/계산 상태 | 시스템 추천 |
|---|---|

| 날짜·금액·전망 범위 부족 | 지급정보 보완. 평시 경로로 임의 처리하지 않음 |

Masil 단독 **영업일 일말 잔액 < 30억원**, 실제 적용 시나리오, 약정 유형, 신규/기존 분류, 지급일·금액·현금 반영 범위와 SCM 인계 상태를 사용한다. 기존 `finance.routing` 및 `finance_review.view`의 결과를 기반으로 `app/finance_advice.py`에서 추천한다. 새 승인권한 규칙을 도입하지 않았다.

추천에는 기준 금액·최저 예상 잔액·부족 기간·약정별 지급일/금액·적용 승인 경로·보완 항목을 함께 표시한다. 실제 발주 대상이 없으면 ‘추가 발주 대상 없음’을 명시한다. ‘현금 기준을 충족한다’는 검토기간 전체의 재무 안정이나 캠페인 성과를 보장한다는 뜻이 아니다.

재무 미확정 시 4개 시나리오의 합집합을 사용해 CEO 상신 필요성을 먼저 판단하며, 확정이 필요하다는 보완 항목을 유지한다. 초안의 현금 반영 범위를 임의 확정하지 않는다. 원본 PO 연결 AP 중복 차감 금지·표본 마케팅 금액 전사 현금 합산 제외·미확인 지급일 자동 추정 금지도 유지한다.

## 화면과 실제 행동

- 시스템 추천 제목을 ‘사람이 검토하세요’에서 구체적인 다음 처리로 바꾸고 해당 재무 의견에 추천 표시를 붙였다. 재무 의견을 자동 선택하지 않는다.
- 추천과 다른 의견에는 사유를 요구하며 실제 승인권한 경로는 규칙으로 계산한다.
- 시나리오를 바꾸면 현금과 추천을 함께 다시 계산한다. 새 `/api/finance-preview`는 GET으로 계산만 하며 DB·재무 확정값을 바꾸지 않는다.
- 저장된 재무 기준과 다른 선택은 가정 검토로 표시하고 ‘선택 가정의 재무 확정 필요’를 남긴다. 원래 CEO 경로를 조회 조작으로 평시 승인으로 낮추지 않는다. 실제 처리 경로는 사람의 재무 확정 이후 다시 산출한다.
- 정보 부족이면 다음 이동도 ‘정보 보완 후 재판정’, 공급 불가이면 SCM 조정 요청으로 안내한다.
- 추천 생성·조회·라디오 선택만으로 상신·승인·발주·지급하지 않는다. 최종 실행은 기존 서버의 검증을 그대로 거친다.
