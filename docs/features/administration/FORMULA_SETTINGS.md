# 단계별 계산식 설정

경로: `/settings` · 담당자 첫 화면과 시스템 관리자에 `계산식 설정` 링크를 추가했습니다.

## 역할별 범위

| 역할 | 수정할 산식 | 범위 |
|---|---|---|
| 마케팅 | 완료 주간 평균 판매, 캠페인 일별 추가 수요 | 2개 |
| SCM | 기본 일별 판매, 현재고/캠페인 커버, 안전재고 참고량, 목표 대비 부족량, 기안 예측 보충량, MOQ 제안량, 발주안 예상 금액 | 8개 |
| 재무 | 발주안 예상 금액, 30억 기준 부족액, 공식 전망 차이 | 3개 (예상 금액은 SCM과 공유) |
| 승인권자 | 전체 조회·변경 이력 확인 | 승인 규정은 이 화면에서 수정하지 않음 |

고유 편집 산식은 12개입니다. 각 카드는 적용 단계·단위·변수·기본식·출처·변경식을 표시합니다. 새 식은 참가자 가정이고 출력은 계산 결과입니다. 시험 입력값은 업무 원본 데이터가 아닙니다.

## 사용

1. 역할 선택 → 산식 수정 → 사칙연산과 변수 또는 허용 함수 입력.
2. `시험 계산`은 예시 숫자만 계산하며 저장하지 않습니다.
3. 수정자·사유·근거 입력 → `변경 영향 확인`. 실제 진행 중인 캠페인에서 변경 전후 판매·커버·재고·조달량·예상 금액을 다시 계산합니다. 재무 역할에는 네 시나리오의 참고 부족액·주별 전망 차이도 표시합니다.
4. 영향 확인 동의 후 `검증한 산식 적용`. 원본 데이터와 기존 기안 입력값을 수정하지 않고 모델 설정을 PostgreSQL에 저장합니다.
5. `기본식 불러오기`도 미리보기와 직접 적용을 거쳐야 합니다. 이는 설정 복원이며 이전 업무 승인까지 복원하지 않습니다.

## 실행과 보관

- 기존 w01_finance.body.formulas에 산식·역할·작성자·사유·근거·시각을 저장합니다. 새 테이블/컬럼이나 파일 저장은 사용하지 않습니다.
- 기존 재무 설정 버전을 동시 변경 제어에 사용하고 w01_events에 변경 전후 식과 영향을 저장합니다. 페이지 이력은 최근 30건을 표시하며 이전 이력도 DB에 유지됩니다.
- 미리보기는 저장하지 않습니다. 적용 시 최신 재무 버전·자료 버전·캠페인 내용에 대한 미리보기 일치 여부를 다시 검사하고 전체 거래를 원자적으로 처리합니다.
- 산식 변경 후 재무 확정은 해제되고 진행 건은 SCM 검토부터 새 근거로 재검토합니다. 재무 참고 지표만 바꾼 경우도 보수적으로 동일하게 처리합니다. 승인 기록은 지우지 않고 현재 근거로 재사용하지 않습니다. 완료 건의 종료 기록과 승인 시점 자료는 보존합니다.
- domain 계산과 통합 portfolio 재고 계산은 같은 산식을 사용합니다. 승인 수요 약속과 실제 공급 회신은 계속 구분합니다. 캠페인 일별 수요식을 변경하면 기존 입력 수량은 보존하면서 예측 일별 수요와 커버에 새 가정을 반영합니다. 승인 시 저장한 성과 비교의 기준 판매 스냅샷은 보존합니다.
- Python eval/exec는 사용하지 않습니다. 제한된 AST로 숫자·변수·사칙연산과 min/max/abs/ceil/floor/round_krw만 계산합니다. 코드 실행·속성/인덱스 접근·거듭제곱·무한 값·0 나눗셈·음수 수요 등을 거절합니다. MOQ 미만 제안도 차단합니다.

## 고정 규칙

일별 재고 수지, 현금 항등식, 연결 AP 중복 차감 방지, 표본/전사 금액 구분, 영업일 30억 기준, 승인권한, 단위 환산, 발주 전달 시 승인 수량×단가 대조는 수정 불가 카드로 모았습니다. 원본 표본 성과 지표와 날짜 가정·업무 종료 조건도 별도 표시합니다. 이 목록은 업무 단계별 주요 계산·통제의 카탈로그이며 프로그램의 모든 날짜 처리·통계 유틸리티를 임의 수식으로 바꾸는 기능은 아닙니다.

발주안 예상 금액은 편집 가능한 **추정 모델**입니다. 실제 전달은 고정된 승인 수량×단가와 지급일 대조를 통과해야 하므로 모델 금액이 다르면 담당자가 단가·금액을 검토하고 재상신해야 합니다. 부족액·공식 전망 차이도 참고 지표이며 현금 잔액이나 CEO 판정을 변경하지 않습니다. 일별 현금 잔액과 결재선은 원본 규정으로 계산합니다.

공유 접속 비밀번호와 역할 선택은 시연용입니다. 서버는 선택한 역할의 산식 수정 범위를 검사하지만 실제 사용자 계정별 RBAC는 구현 범위 밖입니다. 역할을 선택할 수 있는 사용자의 부서 신원을 증명하지 않습니다.

이번 작업은 AX를 위한 계산 모델 관리 기반입니다. 신규 AI 호출·AI 산식 자동 적용·자동 승인·외부 발주·온라인 재배포는 실행하지 않았습니다.
