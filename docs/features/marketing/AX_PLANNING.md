# 마케팅 기안의 수요·공급·현금 사전검토

## 사용 흐름

기존 기안 화면의 헤더·캠페인 입력·SKU 카드·오른쪽 제출 점검 구조를 유지했습니다. SKU 카드 안에 다음 의사결정 도구를 추가했습니다.

1. 캠페인 시작·종료일과 제품을 선택하면 주간 증가 수요, 예상 발주량과 단가가 자동 계산됩니다. 각 값은 직접 수정할 수 있으며 승인·발주는 실행하지 않습니다.
2. 자동 계산된 발주량과 과거 단가 참고값을 확인하고 필요하면 직접 수정합니다. 비용은 수량·단가로 계산합니다. 추가 발주가 필요 없으면 0EA로 표시합니다. 실제 지급일은 승인 후 SCM이 확인합니다.
3. 자동 계산 결과에서 재고·권장 발주·비용과 관련 확인 항목을 확인합니다. 원천 거래 전체를 펼치지 않고 중요한 결과와 확인 항목만 표시합니다. 입력이 바뀌면 이전 결과로 기안을 제출할 수 없습니다.
4. **예측 근거·가정 확인**을 펼쳐 관측 기간·관측 수·참고 범위·기초 판매 검산·출처·한계를 확인합니다. 기안 상신 모달의 수요 근거와 증빙은 해당 자료로 채우며 사람이 수정할 수 있습니다.
5. 기안 저장 시 서버가 최신 자료로 다시 계산해 채택한 수요·기간·금액·소속 기안 총액을 대조하고 `ax_plan`으로 저장합니다. 클라이언트가 보내는 결재선·재고·최저 잔액을 신뢰하지 않습니다.
6. SCM은 같은 근거에서 **수요·공급 확인 · 재무 전달**, 재무는 **현금·결재선 확인 · 승인 요청**을 선택할 수 있습니다. 각 부서 담당자가 이름·사유·근거를 기록해야 하며 확인 없이 단계를 생략하지 않습니다. 최종 승인권자의 기존 승인 화면으로 연결합니다.

사전검토를 사용하지 않은 기존 기안은 기존 상세 검토로 처리할 수 있습니다. 변경/긴급 이슈 또는 미확인 사항이 있으면 간편 확인이 거절되고 기존 상세 검토를 사용합니다. 자료가 바뀌어 사전검토가 오래된 경우 마케팅에서 갱신하거나 기존 상세 검토 절차로 처리합니다.

## 데이터 범위와 예측 방법

- 원본 자금일보의 제공 기간은 2024-01-01~2026-06-30의 30개월입니다. 현금 재전망은 기존 규정대로 6/30 종가와 AR·AP·PO 일정을 사용합니다. 과거 30개월 잔액으로 새 입금이나 그룹 지원을 만들어내지 않습니다.
- 회사 규모 SKU 주간 판매는 2025-01-06~2026-06-29의 약 18개월, 1,092행입니다. 2026-07-01 기준 완료된 마지막 주는 6/22이며 6/29 주차는 제외합니다. SKU당 완료 77주를 확인할 수 있습니다. 30개월 판매 데이터가 있는 것으로 표시하지 않습니다.
- 추가 수요 예측: 같은 제품라인의 과거 캠페인 완료 주 판매 − 해당 캠페인 직전 완료 4주 평균의 SKU별 증분 중앙값(P50), 음수는 0으로 제한합니다. SKU×주 관측 중복을 제거하고 기초 판매는 실제 완료 주 평균으로 계산합니다. 직접 입력도 지원합니다. 관측 4건 미만이면 수요를 비워 두고 직접 입력을 요청합니다.
- 참고 P10~P90은 관측 범위입니다. 미래 신뢰구간이나 성공 확률이 아닙니다. 관측 수 기반 `보통/낮음`도 확률이 아닙니다. 최근 최대 8개 완료 주 WAPE는 기초 판매의 직전 4주 평균 검산이며 캠페인 증분 모델의 예측 정확도를 검증한 값으로 쓰지 않습니다.
- 재고는 기존 통합 SKU 원장의 현재고·확인 공급 회신·다른 승인 캠페인 수요 약속을 한 번씩 반영합니다. 운송 중 수량을 임의로 더하지 않습니다. 공급이 확인되지 않은 조달안은 실제 재고와 구분합니다.
- 권장 발주: 캠페인 기간 최소 예상 재고를 안전재고 참고량까지 보충하는 양을 계산하고, 양수이면 원본 MOQ 최소량을 적용합니다. MOQ 배수 주문을 강제하지 않습니다. 이 목표 자체는 참가자 모델 가정입니다.
- 발주 단가는 동일 SKU의 기준일 이전 최신 기존 PO 단가 참고값입니다. 새 공급 견적이 아닙니다. 희망 입고는 기준일 + 원본 리드타임의 가정입니다. 확인된 공급 회신으로 표시하지 않습니다.
- 비용·현금: 새 발주 예상 비용만 기존 네 현금 시나리오에 가상 차감합니다. 표본 마케팅 예산은 회사 현금에 합산하지 않고 캠페인 결재선 판단에만 사용합니다. 지급일이나 수요가 없으면 가상 발주 후 최저 잔액은 미확인으로 표시하며 임의의 지급일을 채우지 않습니다.

## 간편 확인 조건과 승인 경계

수요 참고 범위·최근 자료·현재 확인 공급·지급일·단가·MOQ·현금 범위·공식 재무 시나리오를 모두 확인할 수 있어야 합니다. 기존 약정 때문에 이미 30억 미만인 기간이 있는지와 해당 캠페인의 새 유출일이 그 기간에 해당하는지는 구분합니다. CEO 대상이더라도 정보·공급 문제가 없다면 부서 확인 후 CEO에게 상신할 수 있으며 시스템이 승인하지 않습니다.

캠페인 기간의 현재 확정 공급이 부족한 상태를 미확인 신규 입고 가정으로 덮어 간편 통과시키지 않습니다. 실제 공급자 회신 확인·공급 조정이 먼저 필요합니다. 데이터/산식/공식 현금 시나리오/다른 캠페인 수요 약속이 바뀌면 저장된 근거를 다시 검토합니다. 이전 확인 이력은 보존합니다.

모델 결과는 계산 결과·참가자 가정입니다. SCM과 재무의 확인은 부서 주장/사람의 검토 기록입니다. 역할별 확인 API는 해당 역할과 단계, 원본 근거·현재 버전·중복 요청 키를 대조합니다. 최종 승인·발주·지급은 생성하지 않습니다. 역할 선택은 기존과 동일한 시연용이며 개인별 부서 인증은 아닙니다.

## 산식·AI 관리

새 `기안 예측 재고 보충량` 산식을 관리자 계산식 설정에 등록했습니다. 기본값은 `max(safety_target - minimum_projected, 0)`이며 SCM이 기존 시험·영향 확인·직접 적용 절차로 관리합니다. 편집 가능한 산식은 12개(SCM 소유 8개, 마케팅 2개, 재무 3개 중 발주 예상 금액 공유)입니다. 기존 완료 주 평균·일별 수요·안전재고·MOQ·금액 설정도 사용합니다. 승인 규칙은 고정 통제입니다.

이번 기능의 예측은 과거 데이터에 근거한 통계 모델입니다. 신규 LLM 호출·유료 AI 실행·관리자 프롬프트의 런타임 연결은 하지 않았습니다. 설명을 생성형 AI가 작성한 것으로 표시하지 않습니다. 실제 예측 효과와 업무 시간 단축률은 향후 실제 운영 검증 대상입니다.

## 실행·검증

- `/api/ax-planning`: 저장하지 않는 사전검토 계산.
- `/api/marketing`의 `ax_inputs`: 기안에 사전검토와 채택 근거를 저장.
- `/api/ax-confirm`: SCM·재무의 명시적 검토/인계. `w01_cases`, `w01_events`를 사용하며 새 테이블·로컬 파일 저장은 없습니다.
- 단위 테스트 157건과 격리 PostgreSQL DB의 기안 → SCM 확인 → 재무 확인 → 승인 대기, 마케팅 화면의 예측/직접 입력/근거 자동 입력/저장, 변경·지급일 누락·공급 부족·자료 변경 예외, 모바일 화면을 검증했습니다. [실행 결과](../../verification/marketing/AX_PLANNING_RESULTS.json).
- 재현: 별도 로컬 테스트 DB에 캠페인 자료를 복제하고 공식 재무 시나리오가 확정된 서버에서 `W01_AX_TEST_BASE_URL=http://127.0.0.1:8089 python3 -m scripts.verify_ax_planning`. 실제 기안을 생성하고 부서 확인을 저장하므로 운영/미리보기 DB를 사용하지 않습니다. Playwright와 Chromium이 필요합니다.

원본 데이터와 시안, .claude/.codex/.agents/.gitignore는 변경하지 않았습니다. 온라인 배포는 이번 범위에 포함하지 않았습니다.

## 예산·일정 계산 동선 보완 (2026-11-11)

예산 영역의 `예산·일정 계산하기`는 같은 페이지의 `SKU·수요·공급 검토` 카드로 이동합니다. 모달로 입력을 복제하지 않고 기존 카드에서 수요·발주·단가를 편집합니다. 계산 결과를 예산 입력 옆에도 상품 조달 예상비용으로 표시합니다. 이는 SKU 수량×단가로 계산한 실제 규모 조달비이며 표본 캠페인 집행 예산을 덮어쓰지 않습니다. 제품명은 SKU 마스터에서 읽기 전용으로 불러옵니다.

리드타임으로 캠페인 시작 전 발주시한을 역산하고, 가장 이른 준비 시한에서 검토 여유 영업일(기본 3일, 내부 관리 가정)을 빼 기안 확정 권고일을 제안합니다. 과거가 된 기한은 가져올 수 없습니다. 사용자가 채택해도 실제 계약 확정기한을 입증한 것이 아닙니다. 추가 발주를 0EA로 명시하면 캠페인 시작일만 기준으로 삼습니다.

캠페인 정산일은 선택한 시작일/종료일 + 직접 입력한 유예 달력일로 제안합니다. 유예일 기본값은 비어 있으므로 리드타임만으로 지급 조건을 추정하지 않습니다. 발주 지급일은 별도로 유지합니다. 각 날짜는 가져오기 버튼을 눌러야 기안에 반영되고, 직접 수정도 가능합니다. 채택한 일정 조건과 수동/산정 구분은 ax_plan.inputs.schedule_terms에 저장하며 서버가 채택 날짜를 다시 대조합니다. 영업일은 월~금, 공휴일 미반영입니다.

상세 구현은 app/planning_schedule.py이며 기본 현금/승인 규칙은 변경하지 않았습니다. [검증 결과](../../verification/marketing/BUDGET_SCHEDULE_RESULTS.json). 재현: 별도 DB의 `[모의 AX] 기안 사전검토` 픽스처에서 `W01_BUDGET_TEST_BASE_URL=http://127.0.0.1:8089 python3 -m scripts.verify_budget_schedule`. 이 명령은 해당 테스트 기안을 수정·저장합니다.
