## 기능과 근거

### 수요 검증

`data/demand_reference.json`은 원본 회사 주간 판매 1,092행과 캠페인 25행의 스냅샷이며 파일명·SHA-256을 보관합니다. 현재 업로드한 회사 판매 자료가 같은 SKU/주차를 대체합니다. 완료 주만 사용하고, 같은 제품라인 캠페인의 관측 판매와 직전 완료 4주 평균의 차이를 계산합니다. 중복 캠페인 주차는 한 번만 세며 관측 건·기간·참고 하위/상위 범위와 한계를 표시합니다.

캠페인 기간이 겹치므로 이는 **관측 참고 범위이며 캠페인의 인과 효과나 검증된 수요예측 모델이 아닙니다.** 과거 범위 밖·관측 부족은 별도 근거와 사람 확인을 요구합니다. 대상 SKU의 수요가 비어 있으면 미확인으로 차단하며 0으로 바꾸지 않습니다. 명시적 0도 작성 근거와 확인이 필요합니다. 대상 SKU 선택 자체도 사람의 책임입니다.

### SKU × 주 계획과 변경

최종 캠페인 승인 시 기간·SKU·순증 수요·승인 근거를 약속 원장에 고정합니다. 다른 기안이 같은 SKU를 사용하면 이 원장을 합산합니다. 기초 판매·현재고는 한 번만 차감하고 확인된 공급은 PO별로 한 번만 더합니다. 같은 PO의 최신 회신이 미확인이면 과거 확정 공급을 계속 사용하지 않으며, 같은 시각의 상충 회신은 경고하고 공급에서 제외합니다.

공급 일정이나 다른 승인 수요가 바뀌면 관련 SKU 검토 근거가 달라지고 재검토 작업이 생성됩니다. 부족한 통합 재고에 대한 추가 캠페인 승인은 서버에서 차단합니다. 확정 약속은 기안 수정·새로고침·재검토·회차 종료만으로 사라지지 않습니다. 변경 수량은 다시 사람이 승인해야 원장을 대체하고, 해제는 원래 승인권한의 명시적 행동을 요구합니다. 과거 승인에 원장이 없으면 `legacy_pending`으로 보수적으로 유지하고 복원 확인 작업을 만듭니다.

실제 모의 전달된 신규 PO는 다른 기안의 현금 전망에도 한 번 반영합니다. 자기 기안의 이미 전달된 PO를 재검토할 때 이중 합산하지 않습니다. 모든 쓰기는 PostgreSQL 트랜잭션·공통 잠금·버전 검증을 사용합니다.

### E1 필수 확장 · 공식 전망과 재전망 비교

공식 전망은 **부서 주장인 주차 값**으로, 지급일의 일말 가용현금 정의가 없습니다. 따라서 공식 주차값을 지급일 잔액으로 본 비교 열은 **참가자 가정·반사실 비교·결재 사용 불가**로 표시합니다. 실제 결재는 동일 재전망 시나리오의 영업일 일말 하회와 신규약정 여부를 사용합니다. 토글은 조회만 하며 확정·승인 상태를 변경하지 않습니다.

원본 seed 기준 공식 주차 최저 5,468,884,369원(54.69억), 보수적 재전망 최저 1,467,664,440원(14.68억). 시연의 1,500만원 캠페인은 비교 가정에서는 Masil 대표+그룹보고지만 실제 재전망으로 CEO/이사회에 상신되어 사람이 승인했습니다. 공식 자료의 7/21 PO 누락은 추정, LC 변경은 원본 근거이며 다음 영업일 입금은 선택 가정입니다. 신규 PO가 기록된 뒤 실제 잔액은 그 유출을 추가 반영하므로 seed 고정값과 달라집니다.

### 담당 작업·체류시간·후속 의무

작업은 확정/담당 기한 → 현금 상위 승인 → 품절·수요 미확인 → 생성 순으로 정렬하고 역할별로 조회합니다. 전이 사건의 이전/이후 단계·담당·상태·실제 UTC 시각으로 완료 체류시간과 현재 대기시간을 집계합니다. 데이터 이전에 관측하지 않은 기간은 추정하지 않습니다. 기한 판정의 가상기업 검토일과 실제 사건 시각을 구분합니다. 짧은 시연 로그를 실제 현업 병목·효과의 인과 증거라고 주장하지 않습니다.

입고 예정 회신과 실제 입고 증빙은 분리합니다. 누적 일부 입고는 작업을 닫지 않고 전량 확인 후 닫습니다. 원본 현재고를 자동 증액하지 않습니다. 실제 판매 검산은 완료 주의 회사 판매 자료가 있어야 하며 미확인을 0 실적으로 완료할 수 없습니다. 주간 현금 재전망은 재무의 다음 검토일 작업으로 유지합니다.

### Human-led 보조 제안

선택적 AI 어댑터에 수요 범위·공유 재고·현금 판정·출처·가정을 전달합니다. 텍스트와 별도로 서버가 허용한 확인 요청/협의 행동만 제시합니다. 사람이 근거·사유를 기록해 채택해야 작업이 생기며, 오래된 근거·임의 행동·중복 채택은 차단합니다. AI 문장으로 계획·권한·승인·발주·지급을 바꾸지 않습니다.

이번 시연은 **규칙 기반 초안 · AI 미연결**입니다. 실제 유료 AI 호출은 하지 않았습니다. 모의 AI가 승인/지급을 요구하는 문장을 반환해도 허용된 작업만 생성되는 것은 단위 테스트로 확인했습니다. 설정 후 실제 모델의 분석 품질 검증은 별도입니다.

서버를 종료하고 같은 PostgreSQL DB로 재시작한 뒤 6개 건의 본문·버전·사건 전체 해시·약속 상태가 동일함을 확인했습니다. 기존 로컬 DB는 보존했고 `w01_upgrade_final`이라는 별도 로컬 검증 DB를 사용했습니다.
