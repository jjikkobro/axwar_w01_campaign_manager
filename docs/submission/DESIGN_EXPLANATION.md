# 제출 설계 설명 · 기획 의도와 구현 범위

사용자가 제공한 7개 문항의 제출 설명을 보존했습니다. 구현 범위와 수치는 작성 당시 설명이며, 현재 재실행한 검증 결과와 구분합니다. 모의 처리와 후속 설계를 실제 운영 연동으로 해석하지 않습니다.

## 1. 고른 업무와 돕는 결정

[고른 업무]
- Masil Commerce의 캠페인 신청 → 추가 발주 → 현금 결재 → 발주·회신을 기안 1건으로 처리

[누가 · 어떤 상황에서 · 무엇을 결정]
- 마케팅: 신규 캠페인 기획 시 신청 여부 (기간·상품·수량·예산)
- SCM: 캠페인 기간 재고 부족 시 추가 발주 여부·수량·지급일
- 재무: 지급일이 현금 30억 원 하회 구간에 걸리는지 확인, 결재선(평시 / CEO) 확정
- 승인권자: 부서 의견·근거를 보고 승인 · 조건부 승인 · 반려

[결정이 어려운 이유]
- 정보 공백: 마케팅이 재고·현금 상황을 모른 채 캠페인 제안
- 판단 지연: SCM(재고·입고)과 재무(현금)가 각자 자료를 수작업으로 대조
- 부서 간 충돌: 지급일이 하회 구간에 걸리면 CEO 승인 대상이 되나, 재무 단계에서야 확인 → 반려·재작업 왕복
- 확인 누락: 미확인 회수일·지급일이 판단을 막아도 담당자·할 일로 남지 않음

[해결 방향]
- SCM·재무의 판단 자료를 마케팅 기획 화면으로 당겨, 기준 미달 건은 신청 단계에서 차단

## 2. 시작과 끝

[시작]
- 마케팅 기안 입력: 기간 · 채널 · SKU · 주당 증가 수요 · 예산
- 현금 전망 기간(7/1~9/28) 밖 일정은 신청 단계에서 차단

[중간: 확인 · 판단 · 승인]
- 계산: 최근 4주 판매 · 재고 · 기존 발주로 재고 커버와 권장 발주량 산출
- SCM: 추가 발주안 작성, GPT의 위험·대안 초안을 확인·수정 후 재무에 인계
- 재무: 4개 현금 시나리오로 하회 구간 계산, 결재선 판정 후 상신
- 승인권자: 승인 · 조건부(발주 차단) · 반려(보완 작업 생성)

[끝]
- 발주서 자동 작성 → 모의 발주 → 모의 공급처 회신 → 품절 여부 재계산
- 마케팅 일정에 입고·지급일 연결 → 회차 종료 기록
- 후속 작업 생성: 실제 입고 확인 · 성과 측정
- 반려 시: 마케팅 보완 → 같은 기안의 수정 버전으로 재신청

[제공 흐름도 대비 변경점]
- 유지: 계획 공유 → SCM 대조 → 재무 검토 → 사람 승인 → 발주·회신 → 일정 정리의 순서·책임
- 추가: 마케팅 단계의 재고·현금 사전 검토와 일정 차단 → 뒤 단계 반려 방지
- 추가: 승인 후 '입고예정 회신 확인' 단계 → 회신이 승인 내용과 다르면 재무 재검토
- 구분: 캠페인 집행 승인과 발주 승인을 분리
- 원칙: 추가 통제는 '내부 통제'로 표시, 원본 승인 권한은 수정 불가한 고정 규칙

## 3. 필수 확장

[더한 것]
- 재무의 현금 30억 원 기준을 마케팅 기획과 발주 결재선 판단에 연결
- 연결 구조: 캠페인 → 추가 발주 → 지급일 → 일별 현금 전망 → 하회 구간 → 결재선
- 예외 처리
  · 지급일 없음·전망 기간 밖 → 판정 불가, 상신 차단, 확인 작업 생성
  · 미확인 미수금·미지급금 → 4가지 경우로 나눠 보수적으로 판정

[경험 반영]
- AX 컨설팅 지향, SCM 실무 경험 부족 → 유사 구조 기업을 AI로 조사하고 현업 담당자 인터뷰로 흐름·병목 파악
- 마케팅 자동화 도구 개발(발행 시간 8시간→3시간) 경험 → 불필요한 업무는 첫 단계에서 차단
- AI 채용 플랫폼·이력서 분석 개발 경험 → 원본 데이터 기반 AI 응답, 출처 명시, 결정은 사람에게 분리

[필요한 이유]
- 원본 승인 규정상 하회 구간의 신규 지출은 CEO·이사회 승인 대상
- 기존 흐름에서는 이를 재무 단계에서야 확인 → 일정 지연·반려 반복

[사용 위치]
- 조회: 마케팅 기안 화면에 현금 전망 기간·재고 표시
- 계산: 4개 현금 시나리오의 하회 구간(7/21~8/28)
- 판단: 결재선 판정 (지급 9/21 → SCM 전결 / 7/21 → CEO·이사회)
- 상태 변경: 신청 차단, 재검토 전환, 확인 작업 생성

## 4. 다른 부서 영향

[영향받는 부서의 목표 · 제약]
- 재무: 현금 30억 원 유지 / 하회 구간 신규 지출은 CEO 승인 필요
- SCM: 캠페인 기간 품절 방지 / 리드타임·최소 주문 수량·확인된 입고만 반영
- CEO·이사회: 꼭 필요한 건만 상신받아야 함

[달라지는 대안 · 승인 · 계획 · 후속 처리]
- 대안: 전망 기간 밖 일정은 신청 차단 → 일정 조정이 먼저 필요
- 승인: 같은 발주안도 지급일 9/21 → SCM 전결, 7/21로 앞당기면 → CEO·이사회로 재판정
  · 캠페인 집행비는 지급일 9/21 그대로 → 마케팅 전결 유지 (유지 근거 표시)
- 후속: 조건부 승인 → 발주 차단·조건 작업 / 반려 → 마케팅 보완 작업 생성
- 계획: CEO 반려 후 마케팅이 증가 수요를 주당 1,000→500EA로 축소 → 추가 발주 0개로 재계산, 선지급 문제 해소
- 재판정: 미수금 6건 회수 확인(모의) → 현금 시나리오 변경 → 8/25 건은 SCM 전결로 변경, 7/21 건은 CEO 유지

[필수 확장과의 관계]
- 같은 사례(현금 30억 원 기준)로 두 요건을 함께 충족

[증거]
- 시연 영상 3장(조건 변경)·4장(반려·재신청), 시나리오 4건 자동 검증 통과

## 5. 데이터

[원본 자료 · 원본 사실]
- 주간 판매: 약 18개월, 기준일 직전 완료 4주(약 30일) 평균 사용, 미완료 6/29 주 제외
- 재고(6/30) · 기존 발주 14건 · SKU 마스터(최소 주문 수량·리드타임)
- 현금(6/30 잔액 약 51.5억 원) · 미수금 · 미지급금
- 승인 규정 · 약정 조건(최소 현금 30억 원) · 산식 정의 문서

[부서 주장 · 사실과 구분]
- 공식 현금 전망: '부서 주장'으로 표시, 재계산 결과와 나란히 비교
- 마감 기준이 불명확해 차이 원인은 '추정'으로만 표시

[직접 세운 가정 · 새 데이터와 이유]
- 캠페인 증가 수요: 과거 유사 캠페인 증가분의 중앙값 → 미래 수요가 원본에 없어서 (사례 4건 미만이면 빈칸, 직접 입력 요청)
- 미확인 미수금·미지급금 처리 4가지 경우 → 실제 회수·지급일 미확인
- 모의 공급처·회수·승인 회신 → 외부 업무 대체

[없던 정보 처리]
- 지급일·회수일은 임의로 채우지 않고 보류
- 재무 확인 작업 생성 → 회신 입력 시 재판정

[관리 원칙]
- 6종 구분 표시: 원본 사실 · 부서 주장 · 참가자 가정 · 내부 통제 · 계산 결과 · 모의 회신
- 원본 파일 76개 변경 없음 확인, 표본 비용은 전사 현금에 미합산, 미지급금 중복 차감 0건

## 6. 작동 범위

[실제 작동]
- 데이터 저장(PostgreSQL), 재고·현금 계산, 결재선 판정·재판정
- 입력 검증·신청 차단, 작업 생성·완료, 처리 이력 기록
- 실제 GPT 호출(단계별 검토 초안), 산식·자료·AI 지침 설정

[모의 처리]
- 공급처 입고 회신, 미수금 회수 확인, 승인권자 결정(승인·조건부·반려)
- 외부 전송 없는 발주 기록
- 단, 회신 입력 이후의 재고·현금·결재선·작업 갱신은 실제 작동

[설계만]
- 개인별 로그인·부서 권한, 은행·공급처 실제 연동, 분할 입고, PDF 내용 자동 추출

[AI가 맡는 일]
- 입력: 기안, 부서 의견, 시스템 계산값, 출처 자료(최근 4주 판매·재고·기존 발주·현금 전망)
- 출력: 요약 · 위험 · 대안 · 확인 질문 · 근거, 문장마다 출처 파일 표시
- 예: "8/17부터 재고 부족 예상, 미확인 기존 발주 10,000EA 입고 확인 필요"
- AI 초안 생성만으로는 상태·승인·발주가 바뀌지 않음

[사람이 승인하는 지점]
- 기안 신청, SCM 인계, 재무 상신, 승인·반려, 발주 전달, 회신 기록, 산식 적용, 자료 저장
- 모두 담당자의 명시적 행동으로만 처리

## 7. 추가 확장 (선택)

[다이나믹 세팅 · 실제 작동]
- 필요: 수시로 바뀌는 규정을 개발자 없이 현업이 반영
- 산식 수정 → 시험 계산 → 변경 영향 확인 → 사람이 적용 → 버전·사유·근거 기록
- 적용 시 진행 중인 기안 재검토, 30억 기준·승인 권한은 수정 불가

[최신 데이터 업로드 · 실제 작동]
- 필요: 판매·재고·현금 자료를 최신으로 유지
- 담당 역할이 CSV 업로드 → 저장 전 형식·변경 검증 → 원본 보존, 사본 버전 관리

[AI 지침 설정 · 실제 작동]
- 단계별 GPT 지침을 화면에서 수정, 다음 생성부터 적용
- API 키는 서버에만 보관

[전체 동작 기록 · 실제 작동]
- 모든 동작을 시각·캠페인·역할·사건으로 기록
- 단계별 대기 시간·반복 재검토로 병목 확인 → 다이나믹 세팅으로 개선

[SCM 정기 보충 · 마케팅 비용 참고안 · 실제 작동(가정 포함)]
- 입고 시점 예상 재고가 안전재고 이하이면 발주 검토 제안
- 유사 캠페인 비용으로 집행비 참고값 제시, 상품 조달비와 분리

[후속 설계]
- 개인 인증·부서 권한, 은행·공급처 실연동, 분할 입고
