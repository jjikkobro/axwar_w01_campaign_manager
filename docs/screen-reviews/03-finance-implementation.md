# ③ 재무 화면 컨펌·반영 기록

2026-11-10 사용자 응답 **“어 진행해”**를 03-finance.md 첫 부분의 여섯 수정 방향에 대한 컨펌으로 기록했다. ③ 화면의 구현·검증 완료. ④ 이후 화면의 컨펌이나 배포 승인은 포함하지 않는다.

## 반영 내용

첨부 원본 HTML·추출 화면은 보존하고, ③의 기존 제목·개요·결재선·현금·성과·판단·규정 섹션에 현재 건의 데이터와 업무 기능을 연결했다. 별도 대시보드나 모달형 기안서를 만들지 않았다.

- 캠페인·발주·전속계약의 승인 대상을 분리하고 대상별 근거·유출일·분할액·기안 총액·연액·원본 PO를 기록한다. 미확인 날짜·금액은 확정하지 않는다. 전사 현금 반영 확인 / 표본 제외 / 미확인 구분을 저장한다.
- 기초 전망과 검토안 영향 전망을 별도 계산한다. 기존 약정은 재차 차감하지 않고 변경 PO는 원본 일정을 대체한다. 여러 신규 지급의 누적 영향도 확인한다. AP 연결분 중복 제외, 4개 연체 가정, 주말 조정, 주간 시나리오 확정과 개별 연체 회신은 기존 API와 연결했다.
- 주간 최저·금요일 일말·공식 주차값을 나란히 표시한다. 9/28주는 관측 1일이며 금요일 범위 밖임을 표시한다. 공식 전망의 마감 정의 미확인을 유지한다.
- 성과 표는 원본 CSV를 A05 기준으로 재계산한다. CMP-0003의 공헌이익 −30,674,334.9원, 명목 ROAS 약 1.28, 실질 ROAS 약 −0.25, 24/25위가 재현됐다. 주문 집단·실제 주문 기간·기준일·주문당 1개·환불/수수료 비용 가정·출처 해시를 표시한다. 이 가정의 값은 미래 집행 성과나 전사 현금이 아니다.
- 관련 INF-001 계약은 연 28억원·7/17 통보기한·별도 승인 카드로 표시한다. 연액을 임의 일자에 현금 유출로 배치하지 않는다. 관련 계약의 승인·통보 대응 확인은 캠페인 상신과 별도 작업으로 관리한다. 계약 통보를 외부로 발송하거나 자동 갱신을 시스템이 취소하는 기능은 없다.
- 담당자·사유·근거·의견·대안·성과 근거를 확인한 뒤 계산/저장/확인 요청/상신한다. 실제 파일 첨부, 확인 질문·회신, 담당자별 작업, 전후 이력, 자료·재무·기안 버전을 DB에 보관한다.
- 상신은 SCM 유효 인계·지급정보·재무 확정·중요 확인 완료 조건을 검사한다. 승인·발주·지급을 생성하지 않으며 ④ 검토 대기를 명시한다. 구버전 저장·중복 상신·다른 역할의 처리 차단을 검증했다. 자료 변경 시 근거 해시가 달라져 재검토로 표시하고 오래된 상신 작업을 유효하게 유지하지 않는다.

## 파일·책임

`app/finance_review.py`: 검토 입력·경로·기초/영향 계산·근거 유효성·확인 작업.
`app/performance.py`: 원본 표본 성과와 출처·가정.
`web/finance-screen.js`: ③ 시안 섹션에 실제 기능 연결.
`app/server.py`, `app/workflow.py`, `web/design.js`, `web/index.html`: 위 기능의 연결만 추가. SCM 병렬 작업의 변경은 보존했다.

`tests/test_finance_review.py`: 미확정 차단, 분할 지급의 금액 기준 우회 방지, 기존 PO 중복, 표본 현금 제외, 버전 무효화, 주간 지표, 원본 성과 등 13개 추가 검증.
