# UI/UX 기준 정정 및 시안 교체

2026-11-10 · 사용자 명시 요청 반영. 기존 독자 UI를 수정하는 접근을 중단하고 첨부 시안을 화면 기준으로 교체했다.

## 최종 목표와 진행 기준

첨부 시안의 **담당자별 독립 페이지·현재 캠페인 진행 플로우차트**를 유지하면서 각 페이지의 입력·판단 근거·결정권자·출력·인계가 원본 W01 업무와 일치하는지 검토하고 적용한다. 현업의 기존 업무를 쉽게 하며, 원본을 벗어나지 않고 AI는 근거 기반 제안만 하는 Human-led 원칙을 유지한다.

진행 순서: 한 페이지의 원본 대조 → 차이와 수정안 제시 → 사용자 컨펌 → 그 페이지 적용·검증·이력. ① 내용에 대한 기존 컨펌은 유지한다. ② 이후 내용·업무 기능은 일괄 컨펌으로 간주하지 않는다.

## 화면 교체 범위

| 구분 | 변경 |
|---|---|
| 기존 독자 UI | 사이드바·대시보드·모달형 기안서와 해당 app.js / marketing.js / style.css 제거 |
| 화면 기준 | 첨부 번들에서 9개 페이지의 본문·섹션·배치·스타일·입력/제품선택 구성을 추출. root 원본 파일은 보존 |
| 전체 진행 | 시안의 캠페인 요약·7단계 플로우·보류 분기·5W1H 및 추천/근거/대안 보고서 영역 유지. 미검토 추천·근거는 시안 예시로 구분. 현재 캠페인 DB 상태로 단계 강조 |
| 담당자별 페이지 | 시안의 마케팅·SCM·재무·승인·보류·발주·회신·기록 페이지를 독립 경로로 탐색 |
| ① 마케팅 | 시안의 머리 → 개요 → 일시/장소 → 대상 → 제품 → 집행 형태 → 예산/매출 → 제출 전 점검·결재선 영역 유지. 컨펌된 출처·제품별 수요·성과·저장 기능 연결 |
| ② 이후 | 시안 예시·검토 대기를 명시. 수치·추천·AI 표시는 현재 캠페인 계산 결과가 아님. 상태 변경 버튼 비활성 |
| 현재 단계와 열람 화면 | DB에서 계산한 현재 단계와 열람 중인 페이지를 구분. 승인 화면을 열어도 승인 대기·승인으로 진행되지 않음 |
| 데이터 | 기존 PostgreSQL·API·계산·이력 보존. UI 초기화를 DB 초기화로 해석하지 않음 |

추출 원본과 보정 범위는 [screens/manifest.json](../../web/screens/manifest.json)에 해시로 기록했다. `python -m scripts.extract_design`으로 같은 소스에서 다시 만들 수 있다. 원본 React/DC 런타임을 실행하거나 외부 폰트·스크립트를 불러오지 않는다. 포함된 로컬 한글 폰트를 사용한다. 바인더는 식별자 경로만 읽으며 eval과 인라인 스크립트 실행을 사용하지 않는다. 원본 인라인 스타일을 유지하기 위해 CSS만 인라인을 허용하며 스크립트 정책은 self를 유지한다.

## ① 내용 컨펌의 시안 페이지 적용

- 원본 PLAN/CMP 값과 미래 요청값을 원래 기안 페이지 안에서 구분. 참조값 불러오기 후에도 원본은 보존.
- 원본에서 확인되지 않은 '기존 양식' 표현 제거. 추가 설계임을 표시.
- 완료된 최근 4주 평균·자료 출처·버전 표시. 원본 하드코딩 평균 대신 기존 자료 사용.
- 제품 선택·제품별 증가 수요 배치 유지. 단위·적용기간·근거·신뢰·판매 중복 정보를 제품 행에 추가. 단순 커버는 공급 확약이 아님.
- GMV 쿠폰 차감 전이라는 단정 제거. 실적 GMV는 쿠폰 반영 후이며 예상 GMV 범위는 별도 확인.
- 원본 고정 하회구간·나머지 24건 예산 상수를 ①의 판정에서 제거. 계획 공유는 승인 미확정으로 표시하고 묶음 근거는 직접 보관.
- 제출 전 점검은 실제 저장 검증 대상에 맞춤. 데이터가 부족하면 미확인 사유와 확인 작업으로 연결.
- 실제 저장·버전·파일 업로드·SCM 요청·수정 이력은 기존 검증된 API 사용. 첨부 버튼이 임의로 '첨부됨'을 바꾸지 않음.

## 원본 업무 흐름 정합성의 현재 판정

W01 원본의 계획 공유 → SCM 재고·입고표 대조 → 재무 금액·권한 검토 → **발주 승인** → 발주·회신 → 일정·기록 순서를 기준으로 삼는다. 시안에 있는 캠페인 집행 승인·계약 확정과 원본의 발주 승인은 같은 것으로 자동 취급하지 않는다.

현재 ① 내용 대조·컨펌은 완료했고 시안 페이지로 재반영했다. ② 이후 페이지의 표·판정·정산/지급·기한·계약 확정 표현 등은 화면별 검토 대상이다. 표시 가능한 9개 페이지가 모두 원본 업무와 동일하다는 뜻은 아니다. 다음 검토는 **② SCM 재고·입고표 대조**다.

## 검증과 한계

- JavaScript 3개 파일 구문 검사 통과.
- 기존 계산·권한·마케팅 회귀 테스트 **39개 통과**: [로그](../verification/screen-reviews/ui-reset-tests.txt).
- 실제 Chromium으로 9개 페이지 전환·7단계 플로우·독자 UI 제거·미검토 버튼 차단 확인.
- 원본 페이지의 세 제품에 제품별 수요·근거 입력 → 실제 PostgreSQL 저장 → 파일 첨부 → 미지원 파일 실패 표시 → 기안 제출 → 현재 단계 ② 표시.
- ④ 화면을 열람한 뒤에도 현재 단계는 ②로 유지됨. 390px에서 가로 넘침 없음. 자료 없음·통신 실패·재시도 화면도 확인.
- 브라우저 증거: [ui-reset-results.json](../verification/screen-reviews/ui-reset-results.json). 재현: 별도 로컬 테스트 서버에서 `W01_TEST_BASE_URL=http://127.0.0.1:8080 python -m scripts.verify_marketing_browser`. 검증용 기안을 생성하므로 운영 환경에서 실행하지 않는다.
- 원본·시안·설정 파일 77개 작업 전후 SHA-256 동일. 운영 DB 삭제·스키마 변경·온라인 재배포·외부 승인/발주/지급·실제 유료 AI 호출 없음.

브라우저는 격리된 로컬 테스트 DB로 검증했다. 실제 사용자 인증은 아직 구현하지 않은 시연 역할이며, 실제 부서의 현업 사용자 검증을 대체하지 않는다. 기존 독자 UI로 수행한 0.3 검증 증거는 당시 이력으로 보존하고 최신 UI 증거와 구분한다.
