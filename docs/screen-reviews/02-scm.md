# ② SCM 재고·입고표 대조 화면 검토

검토일: 2026-11-10. 상태: **검토 완료 / 2026-11-10 사용자 컨펌 / 앱 반영·검증 완료**. 최신 [구현·검증 기록](02-scm-implementation.md)을 확인한다.

## 결론

**페이지 구성은 유지하되 공급 가능 판정·발주안 산출·보완/승인 분기를 수정해야 한다.** 현재 시안은 재고 커버·MOQ·리드타임을 보여주지만, 실제 캠페인 기간과 기존 발주를 대조하지 않고 특정 SKU의 추가 발주를 추천한다. 또한 SCM 공급 불가를 승인권자의 발주 미승인과 같은 보류 분기로 취급한다. 원본과 동일한 업무 흐름이라고 확정할 수 없다.

검토 기준은 첨부 시안의 ② 페이지다. 별도 대시보드나 모달을 새로 설계하지 않는다. 업무 제목 → 개요(5W1H) → 재고·입고표 → 발주안 → 판단·근거·결정 → 검토 규정의 구성과 담당자별 페이지·현재 단계 플로우를 유지한다.

원본에 없는 수요 모델·적정 발주량·확인 작업은 참가자 추가 설계로 구분한다. AI는 출처 기반 제안만 하고 SCM 담당자가 검토 결과를 확정한다. [최우선 Rule](../guides/PROJECT_RULES.md).

## 4. 정량 대조: 기존 발주와 새 발주 초안

| 구분 | SKU-2001 | SKU-2002 | SKU-2003 |

| 기존 발주: 원본 | SPO-0005 | SPO-0006 | SPO-0007 |

기초 3종의 기본 커버 6.17/4.49/5.82주는 모두 원본 리드타임 8주보다 짧다. 이 비교는 세 제품 모두의 기존 보충 일정을 확인해야 한다는 신호이지, 세 제품 모두를 새로 발주하라는 결론은 아니다. 시안의 "나머지 2종은 재고로 충분"에는 판단 대상 기간과 확인 공급 조건이 빠져 있다.

발주일+리드타임은 공급자 확정 회신이 아니다. 원본 발주에 이행 상태가 없으므로 전량 미입고 또는 전량 캠페인 전 입고라고 단정하지 않는다. 운송 중 1,823/1,089/2,459EA와 이 발주 수량 간 관계도 미확인이다.

시안의 SKU-2002 16,000EA·201,600,000원은 기존 SPO-0006과 수량·대금이 같다. 신규 발주안이 잘못됐다는 증거는 아니지만, 기존 발주를 다시 발주하거나 대금을 중복 계산하지 않도록 구분이 필요하다.

- 12,600원/EA = 201,600,000원 ÷ 16,000EA: **계산 결과**, 신규 공급자 견적 아님.
- 2026-08-26 = 가정 발주일 7/1 + 8주: **계산 가정**, 확정 납기 아님.
- 새 발주의 목표 수량·발주일·새 지급일·검수 후 판매가능일은 **미확인**. 기존 7/21 지급일을 새 발주 지급일로 복사하지 않음.
- 원본 Suggested Order Qty에서 운송 중 수량을 차감하는 것과 날짜별 공급에서 확인된 물량만 반영하는 것은 서로 다른 계산이다. 미확인 입고 때문에 날짜별로 보수적으로 보는 경우에도 원본 기준식 자체를 바꾸지 않는다.

## 5. 커버 경고와 캠페인 이행을 분리해야 하는 이유

**설명용 가정:** 기준일 7/1, 미래 캠페인 7/13~19, 증가 수요가 이 7일에만 발생, 기존 판매와 증가 수요를 일별 균등 배분, 확인된 입고 0. 이는 원본에 없는 참가자 가정이며 실제 추천안이 아니다.

| SKU | 주간 증가 가정 | 7/19 일말 재고: 계산 |
|---|---:|---:|
| SKU-2001 | +600EA | 13,497.75EA |
| SKU-2002 | +1,000EA | 6,659.00EA |
| SKU-2003 | +500EA | 11,638.75EA |

이 가정에서는 SKU-2002의 증가 지속 커버가 4주 미만이어도 캠페인 종료 시 재고는 양수다. 따라서 **안전재고 미달 = 캠페인 공급 불가**가 아니다. 반대로 입고 없이 판매가 계속되면 이후 보충 문제가 남는다. 일별 균등 모델은 라이브 당일 피크나 물류 처리능력을 보장하지 않는다.

원본 CSV를 별도 Decimal 계산으로 재검산하고 기존 앱 계산과 교차 확인했다. 세 SKU의 완료 4주 평균과 7/19 기말재고가 모두 일치했다. DB나 가상 공급자 회신은 생성하지 않았다. 상세 값·원본 행 번호·해시는 [02-scm-evidence.json](../verification/screen-reviews/02-scm-evidence.json).

## 6. SCM이 확인·결정할 내용과 부서 인계

| 구분 | 담당자에게 보여줄 내용 | 부족할 때의 처리안 |
|---|---|---|
| 마케팅에서 받은 조건 | 기안 버전·캠페인 기간·SKU별 수요/단위/적용기간/근거/중복 여부·정산 요청일·계약기한 | 누락된 수요·기간은 ① 보완 요청. 표본 주문에서 임의 확대하지 않음 |
| 기존 자료 | 현재고·재고 기준일·완료 4주 평균·안전재고 범위·MOQ·리드타임·기존 PO | 원본/담당자 수정 자료와 계산을 구분. 자료 없음은 미확인으로 표시하며 0으로 대체하지 않음 |
| 공급 회신 | 해당 PO 또는 조달안 ID·확인된 잔여량·입고일·검수 후 판매가능일·근거·회신 상태 | 의존하는 입고일/수량만 공급자 확인 작업 생성. 관련 없는 모든 공급자 회신을 강제하지 않음 |
| 공급 판단 | 캠페인 기간에 충족 가능한지, 부족 일자/수량, 안전재고 위험, 근거로 사용하지 않은 미확인 물량 | 필수 공급 조건 미확인 시 ② 추가 확인 대기. 현재고만으로 기간을 충족하면 미사용 입고 정보는 위험으로 명시 가능 |
| 조달 검토 | 기존 PO 확인/변경, 별도 신규 발주, 추가 조달 없음, 판단 대기 중 선택. 목표·원본 산식·MOQ 전후 수량·추정 금액 | 목표나 지급일 등을 자동 창작하지 않음. 조달안은 미승인 초안 |
| 마케팅 협조 | 부족을 줄일 수 있는 기간·수량·구성 변경 후보 | 승인 전 보완 작업. SCM이 캠페인 계획을 묵시적으로 바꾸지 않고 합의된 수정 버전으로 재검토 |
| 재무 인계 | 기안/자료 버전, SCM 결과·미확인 위험, 조달안별 수량/추정액/원본 PO/신규·변경 요청, 요청 지급일·근거 | ③에서 실제 유출일·금액·신규 여부·현금 시나리오·승인 경로 확인. ②는 이를 대신 확정하지 않음 |

Corevia 생산 제약은 **필요한 조달안에 한해** 확인한다. 기초 SKU는 PL-01/L-01 85%, 더마는 PL-02/L-02 97%다. 공장 평균이나 15% 여유만으로 SKU별 추가 생산·조기 입고를 약속하지 않는다. 실제 생산 슬롯·기존 고객 납기·자재·검수 확인이 필요하면 SCM의 공급자 확인 작업으로 연결한다. 원본에 없는 생산 배정값을 만들어 기본 사실로 쓰지 않는다.

## 7. 업무 상태와 Human-led 경계 — 컨펌 요청

기존의 3개 처리 방향 버튼은 유지한다. 다만 '재고로 가능'은 추가 발주가 영원히 불필요함을, '추가 발주 필요'는 이번 캠페인 공급 불가를 뜻하지 않도록 제품별 공급 판단과 조달안을 함께 기록한다. **추가 확인 대기**를 별도로 제공해 미응답을 거절이나 승인으로 처리하지 않는다.

제안하는 상태·작업 연결은 참가자 내부 통제다. 원본에 이미 있는 회사 규정으로 표시하지 않는다.

1. ① 제출 → ② SCM 확인 작업과 현재 기안 버전 조회.
2. SCM은 수요·재고·기존 발주·회신을 대조. 필요한 확인 작업을 생성하고 미확인 조건을 표시.
3. 담당자가 검토 결과·사유·대안·근거를 명시적으로 저장.
4. 중요 공급 조건 미확인/수요 보완 필요 → ② 안에서 확인·보완 작업 대기. 승인권자의 정식 반려나 업무 회차 종료로 표시하지 않음.
5. 검토 완료 인계 → **③ 재무 확인 작업** 생성. 공급 불가 의견도 SCM 검토 의견이며, 정식 승인·미승인 결과를 자동 생성하지 않음. 확정 불가능한 계획은 마케팅 보완 후보와 위험을 함께 인계.
6. ④ 정식 발주 승인/미승인 → 후속 ⑤/보류 분기. ②에서 발주서 전달·지급·캠페인 계약 확정 실행 금지.
7. 마케팅 수요·기존 발주·공급 회신이 바뀌면 관련 SCM 결과를 재검토 대상으로 표시. 이전 판단·회신·근거는 이력으로 보존.

AI는 근거 요약과 대안·확인 요청의 초안만 제안한다. 모든 최종 SCM 판단에는 결정자·시각·사유·적용 기안/자료 버전을 남긴다. 추천에 동의했다는 사실만으로 검토 책임을 대체하지 않는다.

## 8. 컨펌 후 구현·검증 범위

- 시안의 ② 구성과 ①~⑦ 플로우 유지. 현재 기안·다중 SKU·완료 4주 자료로 연결.
- 현재고·기존 발주·확인 회신·참고 커버·기간별 공급 검토를 같은 페이지에서 대조.
- 목표 수량 미확정 시 발주량 미확정. 원본 권고 산식의 운송 중 차감과 날짜별 공급 반영 구분.
- 기존 발주/변경 요청/신규 발주 구분, 공급일·지급일 미확인 상태 및 확인 작업.
- SCM 검토 결과·근거·작성자·버전·수정 전후를 DB 이력으로 저장. 중복 저장·버전 충돌 검증.
- 사람이 인계한 경우에만 ③ 작업/현재 단계 갱신. 단순 열람·AI 초안 생성으로 변경하지 않음.
- 미확인 회신, 캠페인 기간 변경, 조기 입고 불가, 가격·지급일 미확인, 복수 SKU 및 기존 PO 중복 가산 방지를 검증.
- ③ 화면의 상세 설계와 ④ 승인 기능은 이번 컨펌에 포함하지 않음.

이 문서는 최초 검토 당시의 근거와 수정안이다. 이후 사용자 컨펌에 따라 ② 앱 구현·격리 로컬 DB·브라우저 검증을 완료했다. 원본 시안·원본 데이터·보호 설정은 보존했고 운영 DB·온라인 배포는 변경하지 않았다.
