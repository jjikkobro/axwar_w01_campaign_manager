# ① 마케팅 화면 반영·검증 기록

이 문서는 0.3 최초 반영 당시 기록이다. 이후 사용자 UI/UX 기준 정정으로 해당 독자 UI는 제거했고, 내용·API를 첨부 시안 페이지에 재연결했다. 최신 화면·검증은 [ui-reset.md](ui-reset.md)를 확인한다.

2026-11-10 · 사용자 컨펌과 추가 Human-led 조건 반영 · 로컬 코드 완료, 온라인 미배포.

## 적용한 Rule

[PROJECT_RULES.md](../guides/PROJECT_RULES.md): 현업 담당자의 기존 업무를 쉽게 하는 것이 최우선이다. 원본 업무 순서·부서 책임·승인권한·값의 의미를 보존한다. AI는 출처와 가정이 명확한 제안만 하고 담당자가 확정한다. 원본에 없는 입력·편의 기능은 추가 설계로 구분한다.

정책은 app/policy.py, API의 project_policy, 업무 기준 화면, 기안 안내, AI 프롬프트·검토 패킷에 연결했다. AI 생성은 도구 실행 없이 초안만 저장하며 승인·발주·지급·업무 상태를 확정하지 않는다. 이번에는 실제 유료 AI 호출을 하지 않았다.

## 변경 내용과 업무 효과

| 기존 제약 | 반영 내용 | 현업 부담·업무 경계 |
|---|---|---|
| 원본 기안과 미래 계획의 구분 부족 | PLAN/CMP 원본값·과거 기간·출처/해시를 보존하고 요청값 별도 저장 | 필요할 때 원본값을 불러와 재입력 감소. 원본값을 바꾸지 않음 |
| 단일 SKU, 기간 전체 수량만 입력 | 여러 SKU의 EA/주 또는 기간 EA·기간·근거·신뢰·중복 여부 분리 | 제품별 수요를 한번에 공유. 환산은 계산 가정이며 공급 확약 아님 |
| 평균 판매 기준이 시안과 불일치 | 완료된 최근 4주·자료 출처/버전 표시 | 기준일에 따른 재계산. 원본 현재고를 임의 수정하지 않음 |
| 예산과 약정 유출액 혼동 가능 | 요청 예산·예상 GMV·성과 근거·정산 요청일 별도 저장 | 예산은 현금 전망에 자동 가산하지 않음. 재무 유출일 확인을 대체하지 않음 |
| 정보가 부족하면 가상의 값 입력 위험 | 성과 미확인 사유와 확인 작업 | 모르면 미확인으로 공유. 직위·장소 등은 선택 입력 |
| 시안의 첨부·제출은 표시 전환 | 실제 DB 저장 후 첨부·SCM 인계 작업·이력 기록 | 저장과 SCM 검토 요청을 구분. 중복 생성·동시 수정 충돌 방지 |
| AI 근거 확인 어려움 | 출처 파일·자료 버전·주차·가정·제품별 결과 패킷 공개 | 문장만 믿고 결정하지 않고 사람이 원본과 계산을 검토 |

새 마케팅 기안은 `marketing_plan`이라는 기록 유형이며 새로운 승인 유형을 만든 것이 아니다. 마케팅 계획 공유와 캠페인 집행 승인·파생 발주 승인을 구분한다. SCM 확인 작업까지 연결했고, ② 이후의 상세 검토·발주 건 연결은 해당 화면 검토·컨펌 후 구현한다. 현재 새 기안에서 승인·발주 API를 우회 호출해도 차단된다. 기존 단일 SKU 검토 건의 조회·수정·계산·승인 로직은 유지한다.

## 인수 조건 검증

[12개 인수 조건](01-marketing-acceptance.md)을 기준으로 확인했다.

| 조건 | 검증 결과 |
|---|---|
| 1–2. PLAN/CMP·원본과 새 계획 | PLAN-001의 원본 예산 18,962,703원·GMV 213,330,410원·정산 7/27·기한 7/17·CMP-0003 과거 기간 보존. 요청 예산을 900원으로 수정해도 원본 유지 |
| 3. 다중 SKU·검증 | SKU-1001/2001의 별도 수요·기간·근거 저장·재조회. 중복·음수·NaN·소수 수량·기간 역전 거절 |
| 4. 완료 4주 | 6/1·8·15·22, 1001=8,320.75 / 2001=4,079.25 / 2002=4,319 / 2003=3,911.25 EA/주 |
| 5–6. 단위·참고 커버 | 700 EA/주 × 7일 = 700 EA, 다른 제품은 100 EA/기간. 제품별 적용 기간 밖 추가 수요 0. 다른 SKU의 공급 회신을 중복 가산하지 않음. 자동 발주·취소 없음 |
| 7. 성과 미확인 | 미확인 사유 저장, SCM 인계 시 마케팅 성과 확인 작업 생성. 임의 공헌이익 생성 없음 |
| 8. 실제 첨부·제출 | TXT 내용을 DB에 저장 후 다운로드 바이트 동일 확인. 저장·첨부 응답은 커밋 후 반환 |
| 9. 버전·인계·중복 | 작성 중에는 인계 작업 없음. 명시적 요청 후 SCM 작업 생성. 동일 생성 키 재전송은 같은 건 반환. 오래된 수정 버전은 409. 작성자·수정 전후·사건 이력 저장 |
| 10. 권한 경계 | 승인 미확정 표시. 승인·재무 평가 우회 호출 차단. AI/규칙 초안 생성 후 승인값·기안 단계 불변. 예산 수정 전후 현금 4개 시나리오 동일 |
| 11. 기존 기록 호환 | 기존 단일 SKU API 생성·재조회·계산, 기존 31개 회귀 테스트 통과 |
| 12. 원본 보존 | 작업 전후 보호 파일 77개 SHA-256 동일. 원본 데이터·시안·설정 폴더·.gitignore 보존 |

검증 결과: 단위·회귀 **39개 통과**, 격리 PostgreSQL 통합 **12개 확인 통과**, Chromium 입력·저장·첨부·인계·새로고침·390px 화면 검증 통과. 실제 현업 사용자 테스트나 운영 DB 통합 테스트는 아니다.

실행 증거: [DB 결과](../verification/screen-reviews/01-marketing-results.json), [브라우저 결과](../verification/screen-reviews/01-marketing-browser.json), [테스트 로그](../verification/screen-reviews/01-marketing-tests.txt).

재현: 별도의 로컬 테스트 DB에 migrate·seed 후 서버 실행. `python -m unittest discover -s tests -v`, `W01_TEST_BASE_URL=http://127.0.0.1:8083 python -m scripts.verify_marketing`. 선택 브라우저 검증은 별도 Playwright/Chromium 환경에서 `python -m scripts.verify_marketing_browser`. 검증 스크립트는 모의 건을 생성하므로 운영 환경에서 실행하지 않는다.
