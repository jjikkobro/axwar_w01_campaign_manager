# ③ 재무 금액·승인권한 검토

검토일: 2026-11-10. **검토 완료 / 2026-11-10 사용자 컨펌 / 구현·검증 완료**.

사용자 응답 “어 진행해”로 아래 여섯 수정 방향을 확정했다. 반영 결과와 실행 증거는 [03-finance-implementation.md](03-finance-implementation.md). 아래 검토 본문의 “제안·컨펌 후” 표현은 당시 검토 기록으로 보존한다.

대상은 첨부 시안의 S3_FinReview.dc.html(추출본 web/screens/03.html)이다. 원본 시안·앱·DB는 수정하지 않았다. 다른 세션과 충돌하지 않도록 이 검토 문서와 전용 증거 파일만 작성했다. 검토 방법은 HTML·내장 로직 정적 대조와 원본 CSV 독립 재계산이며, 브라우저 동작이나 DB 저장을 검증한 결과는 아니다.

## 결론과 컨펌 요청

기존 제목 → 개요 → 결재선 → 현금 전망 → 성과·비용표 → 판단·근거·결정 → 규정 구성을 유지한다. 다음 여섯 가지 보완을 제안한다.

1. 캠페인 집행·재고 발주·연간 전속계약을 별도 승인 대상으로 연결한다. 재무는 금액·권한을 검토하고, 최종 승인권자가 명시적으로 승인한다.
2. 기초 전망과 신규·변경 약정 반영 전망을 분리하고 미확정 지급일을 확정 결재선으로 표시하지 않는다.
3. 네 현금 시나리오·연체 회신·주간 확정·기한 전 수시 확인을 현재 자료와 연결한다. 합집합은 내부 통제로 표시한다.
4. 성과 표에 집계기간·비용 가정·표본 한계를 표시하고 쿠폰·환불 중복 차감을 방지한다. 원본 규모가 다른 예산·전속계약 금액을 표본 실적과 직접 합산하지 않는다.
5. 7/17 캠페인 확정기한과 전속계약 해지·조건변경 통보기한을 별도 추적한다. 상신만으로 기한 대응이 완료됐다고 표시하지 않는다.
6. 재무 담당자가 근거·사유·버전을 확인한 후에만 저장·상신한다. 추가 확인은 실제 작업으로 연결하고 변경 시 재검토한다.

이 여섯 항목은 **③ 화면만의 컨펌 범위**다. ②·④ 화면의 컨펌이나 구현을 대신하지 않는다. 프로젝트 최우선 [Human-led 규칙](../guides/PROJECT_RULES.md)을 따른다.

## 컨펌 후 구현·검증 범위

③ 페이지 구성 안에서 현재 기안과 SCM 인계 연결, 승인 대상별 지급 스케줄, 기준/영향 전망, 주간 확정·연체 확인, 성과 근거·관련 계약·기한, 저장·상신 이력을 구현한다. 확인된 기존 데이터는 미리 채우고 변경·미확인 부분만 확인해 담당자의 반복 대조 부담을 줄인다. 추가 입력은 원본에 없는 새 회사 의무가 아니라 판단 근거 보완임을 표시한다.

검증할 상황은 지급일 미정/전망 범위 밖/분할 지급, 기존 PO 중복, 신규 유출로 하회가 새로 생김, 연체 미응답과 회신, 주말 조정, 평시 금액 경계(1천만원·1억원·10억원), 캠페인과 계약의 별도 기한, 다중 SKU·복수 조달, 자료 변경 후 재검토, 저장 충돌·중복 상신·권한 우회, AI 초안/열람으로 상태 불변이다. 주간 최저와 금요일 잔액은 별도 검증한다.

④ 최종 승인·⑤ 발주 기능 및 다른 화면 수정은 별도 컨펌 범위다. **③ 컨펌을 받은 뒤 구현·실행 검증·변경 이력을 기록한다.**
