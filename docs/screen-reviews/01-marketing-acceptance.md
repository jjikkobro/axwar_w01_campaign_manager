# ① 마케팅 화면 구현 대응·인수 조건 — 컨펌 후 검증 기준

작성일: 2026-11-10. 현재 프로토타입의 app/domain.py validate_case 및 web/app.js caseForm을 직접 대조했다. 2026-11-10 사용자 컨펌과 추가 Human-led Rule을 반영했다. 아래 항목은 구현 제안이지 원본에 존재하는 고정 업무 규정이 아니다.

## 1. 현재 저장 구조와 필요한 보완

| 시안의 정보 | 현재 앱의 상태 | 컨펌 후 구현 기준 |
|---|---|---|
| 건명·미래 집행 기간 | title/start/end 보유 | 기존 필드를 유지하고 과거 캠페인 기간과 분리 |
| 작성 부서·성명·직위·작성일 | 기안 작성자 필드 없음. 사건 이력은 시연 역할과 서버 시각 중심 | 작성 부서·작성자·가상기업 작성일 저장. 직위는 선택. 실제 로그인 사용자 인증으로 오인하지 않음 |
| 목적·배경·타깃·집행 방식·장소 | evidence 하나만 존재 | 기안 서술 필드를 분리해 저장. 장소는 선택 |
| 기안 ID·참조 캠페인 | proposal_id는 있으나 마케팅 원본 PLAN/CMP 관계와 동일한 개념은 아님 | 원본 참조 PLAN/CMP와 내부 검토 ID·버전을 별도 보관. 새 기안인지 기존 기안 변경인지 구분 |
| 국가·SNS·포맷·판매채널·인플루언서 | 저장 필드 없음 | 원본에서 불러온 값/새 계획값/수정 이력을 구분. 코드와 표시명 보관 |
| 여러 SKU | sku_id 한 개만 저장 | 제품별 목록을 저장하고 각 SKU의 수요·근거·가정을 분리. 첫 SKU에 전체 수요를 몰아넣지 않음 |
| 주당 증가 수요 | quantity는 캠페인 기간 전체 추가 수요 | EA/주와 기간 전체 EA를 혼용하지 않음. 입력 방식·적용 기간·환산 근거·수정값을 명시. 환산 자체는 계산 결과 |
| 현재고·완료 4주 평균·참고 커버 | 계산 가능 | 참조 기준일과 주차를 표시. 직접 수정하려면 부서 데이터 관리의 출처·버전 절차 사용 |
| 예산·예상 GMV | requested_amount는 약정 유출액/증가분이고 예산과 동일하지 않음. 예상 GMV 필드 없음 | 요청 예산·예상 GMV·약정 유출액을 별도 필드로 저장. 표본 예산을 전사 현금에 자동 더하지 않음 |
| 비용·환불·성과 근거 | 기안별 비용/성과 구조 없음 | 확인 자료·계산 범위·예상 공헌이익 또는 미확인 사유와 확인요청을 보관. 확정 수치처럼 표시하지 않음 |
| 정산일·계약기한 | requested_payment_date/contract_deadline 보유 | 마케팅 요청일과 재무가 확인한 유출일을 분리. 날짜 역전·누락을 숨기지 않음 |
| 첨부 | 검토 건 생성 후 DB 첨부 가능 | 기안 저장 후 파일 업로드 가능. 첨부 완료는 실제 파일 저장 성공을 기준으로 표시 |
| 결재선 | approval_type별 계산 가능 | 마케팅 계획 제출, 캠페인 집행 승인, 파생 발주 승인을 혼동하지 않음. 기안 제출만으로 어느 승인도 확정하지 않음 |
| SCM 인계 | 현재 request 액션과 일반 회신 대기 상태 | 제출 성공과 SCM 확인 작업을 연결. SCM의 상세 검토 화면/발주 판단은 ② 컨펌 이후 별도 반영 |

새 필드의 이름·JSON 구조는 컨펌 후 기존 기록의 호환성을 확인하며 정한다. 이 문서를 근거로 미리 운영 DB를 변경하지 않는다.

## 2. 컨펌 후 확인할 인수 조건

1. 원본 PLAN-001을 참조하면 예산 18,962,703원·예상 GMV 213,330,410원·7/27 정산일·7/17 계약기한을 출처와 함께 확인할 수 있다. 새 계획값을 바꿔도 원본값과 과거 기간은 보존된다.
2. 기존 캠페인 CMP-0003(과거 기초/INF-001/국내/YouTube 숏츠/라이브)과 미래 확대 계획의 기간·상품을 구분한다. 다른 제품군을 선택하면 차이를 경고하되 원본에 없는 금지 규정을 만들지 않는다.
3. SKU 두 개 이상을 선택하고 각각 다른 수요·기간·근거를 입력하면 모두 저장·재조회된다. 음수·NaN·중복 SKU·기간 역전은 서버에서 검증한다.
4. 합의한 완료 4주 정책에서 SKU-1001 평균 8,320.75, SKU-2001 4,079.25, SKU-2002 4,319, SKU-2003 3,911.25를 재현하며 사용 주차를 표시한다.
5. 주간 증가 수요 입력을 캠페인 전체 수량으로 오인하지 않는다. 기간 환산 시 계산 가정을 표시하고 판매 가능 확약으로 취급하지 않는다.
6. 커버 미달은 SCM 확인 사항이다. 마케팅 단계의 단순 비율만으로 자동 발주·자동 취소·공급 충분을 확정하지 않는다.
7. 성과 근거가 없으면 '미확인' 및 확인 요청을 남길 수 있다. 임의의 공헌이익을 만들거나 표본 GMV를 전사 매출로 환산하지 않는다. 실제 집행 승인 단계의 근거 요건은 후속 화면에서 별도로 검토한다.
8. 첨부가 실패하면 첨부 완료를 표시하지 않는다. 제출이 실패하면 제출 완료나 SCM 작업 생성을 표시하지 않는다.
9. 제출 성공 시 기안 버전·출처·작성자와 SCM 인계 작업이 DB에 남는다. 연속 클릭으로 같은 요청이 중복 생성되지 않는지 확인한다.
10. 재무 미확정이면 결재선은 잠정 또는 판정 불가다. 하회구간을 고정 상수로 넣지 않고 유효한 재무 근거를 참조한다. 승인권자·SCM의 권한을 마케팅 입력으로 대체하지 않는다.
11. 기존 단일 SKU 검토 건이 읽기·계산·이력에서 계속 열리고, 새 다중 SKU 건과 혼동되지 않는다.
12. 새 화면에서 제출·수정해도 원본 데이터 및 보호 설정 파일이 변경되지 않는다.

## 3. 진행 경계

이 문서 작성은 검토 근거 보완이다. ① 사용자 컨펌 후 로컬 앱에 반영하고 격리 PostgreSQL·브라우저로 검증했다. 운영 DB 변경·온라인 배포는 하지 않았다. ② 이후 화면은 별도 검토·컨펌 대상이다.
