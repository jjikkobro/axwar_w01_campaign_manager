# W01 프로젝트 최우선 Rule

규칙 ID: W01-HUMAN-LED-1 · 2026-11-10 사용자 확정. 출처 구분: **내부 통제(사용자 지시)**. 원본 기업 규정이 새로 존재하는 것으로 취급하지 않는다.

**현업 담당자가 기존에 하던 업무를 더 쉽게 진행하도록 돕는 것이 최우선 목적이다. 기존 업무 흐름과 원본의 의미를 벗어나지 않는다. AI는 명확한 근거를 기반으로 제안하며, Human-led로 운영한다.**

- W01의 계획 공유 → SCM 재고·입고표 대조 → 재무 금액·권한 검토 → 사람의 발주 승인 → 발주·회신 → 일정·기록 정리 순서와 책임을 보존한다. 캠페인 집행 승인과 발주 승인을 구분한다.
- 원본 파일·원본 값·단위·날짜를 보존한다. 수정 요청값과 원본 참조값은 별도로 보관한다. 원본 사실 / 부서 주장 / 참가자 가정 / 내부 통제 / 계산 결과 / 모의 회신을 구분한다.
- 원본에 없는 필수 입력이나 통제를 현업의 기존 규정이라고 표현하지 않는다. 추가 설계는 업무 부담·효용·원본 근거를 검토한 뒤 사용자 컨펌 범위에서만 적용한다. 확인되지 않은 내용은 확인 요청으로 넘긴다.
- AI 제안은 출처 파일·관련 행 또는 조항, 계산 기준·기간, 가정·불확실성을 함께 제시한다. 출처가 없으면 미확인이라고 표시한다. AI 문장 자체는 검증된 사실이나 승인 근거를 대체하지 않는다.
- 자동 계산·경고·작업 생성은 담당자 검토를 돕는다. 계획 제출·데이터 수정·재무 확정·상신·승인·발주는 담당자의 명시적 행동으로 처리한다. AI 출력으로 업무 상태·권한·지급을 변경하지 않는다.
- 모든 화면은 **검토 → 사용자 컨펌 → 해당 화면 구현·검증·이력 기록** 순서로 진행한다. ① 컨펌을 다른 화면 컨펌으로 확대 해석하지 않는다.

## UI/UX 기준 정정 · 2026-11-10 사용자 확정

첨부한 `W01 전체 흐름·병목 화면 시안.html`을 UI/UX 기준으로 삼는다. 기존에 별도로 제작한 사이드바·대시보드·모달형 기안서를 수정하는 방식은 중단하고 시안의 담당자별 독립 페이지·현재 캠페인 단계 플로우차트로 대체한다.

페이지의 배치·섹션·질문·판단·다음 담당자 인계는 시안을 기준으로 검토한다. 원본 W01 흐름·부서 책임·승인 규정과 불일치하는 내용만 근거와 함께 수정한다. ① 내용 컨펌은 유지하되, ① UI는 첨부 시안의 페이지 구성에 반영한다. 이후 페이지는 시안 표시와 실제 업무 기능 적용을 구분하고 화면별 컨펌 후 연결한다.

각 화면 검토 시 기존 업무의 입력·담당자·판단 근거·출력·다음 담당자 인계를 연결한다. 변경을 제안할 때는 줄어드는 반복 작업과 추가되는 입력 부담을 함께 검토한다.

실행 정책: [app/policy.py](../../app/policy.py). AI 초안은 정책과 자료별 출처를 포함하며 기존 승인 서버 검증을 우회하지 않는다.

## 최종 Goal 적용 범위 · 2026-11-10 사용자 확정

사용자의 5개 우선순위 구현 요청은 통합 계획·수요 검증·공식/재전망 비교·담당 큐/체류시간·공유 사건과 관련 협의/후속 의무 구현을 승인한 것입니다. 이 범위에는 별도의 화면별 재컨펌 없이 적용·검증·이력을 남깁니다. 이전 개별 화면 컨펌 대기는 이 범위를 중단시키는 조건이 아닙니다. 기본 원본 시안 13개 화면과 업무 순서·책임·승인권한, 표본/실제 규모 구분은 유지합니다. 추가 통제와 통계적 가정은 원본 규정과 구분하며, 수요·협의·계획·승인 확정은 사람이 합니다. [적용 보고](../features/workflow/W01_UPGRADE.md).

## 캠페인 운영 표시 범위 · 2026-11-10 사용자 확정

연체 회수·별도 인플루언서 전속계약 등 캠페인 운영 외 업무는 화면의 검토 대상·담당 작업·후속 의무에서 제외한다. 원본·DB와 현금/승인 판단에 필요한 내부 계산은 보존한다. 제외를 삭제·승인·완료로 해석하지 않는다. 캠페인의 매체·성과 정보와 관련 발주/현금 제약은 유지한다. [적용 기록](../features/workflow/CAMPAIGN_SCOPE.md).


## 공통 산식과 페이지 일관성

- 새 산식·기본값·입고/역산 일정은 app/formulas.py와 app/planning.py 등 공통 서버 계산에 등록하고 필요한 모든 역할 화면에서 같은 결과를 조회한다. 페이지별로 같은 업무 산식을 다시 구현하지 않는다.
- 산식 변경은 관련 마케팅·SCM·재무·승인·발주·회신/일정 검산에 함께 적용하고 사용 화면을 명시한다. 화면을 추가할 때 계산 기준 변경 감지와 오래된 요청 차단을 연결한다.
- 공통 기준 변경 시 입력 중 값을 보존하고 오래된 예상안은 재계산한다. 기존 기안도 변경된 경우 동시 수정 충돌을 건너뛰지 않는다.
- 원본 사실·실제 발주/입고 회신·기존 승인·담당자의 명시적 채택값을 계산 추천으로 자동 덮어쓰지 않는다. 현재 계산과 당시 기록은 구분한다.
- 관련 페이지의 동일 입력/동일 결과, 변경 전파, 권한 경계와 실제 기록 불변성을 회귀 검증한다.
