기준일은 케이스 기준인 2026-07-01입니다.

## 2. 화면 간 흐름

```
마케팅   ① 기안 ──▶ 대기 ─────────────────────────────▶ ⑦ 일정표 정리 ──▶ (다음 기안)
                     └─ ④ 반려 시 ──▶ 보류·재검토 ──▶ ① 재상신 / 철회
SCM            ② 대조 ──▶ 결재 대기 ──▶ ⑤ 발주 ──▶ 회신 대기 ──▶ ⑥ 회신 확인 ──▶ (마케팅 ⑦)
재무                  ③ 검토·상신 ──▶ 대기·감시 ──▶ 주간 재전망 / ⑥ 지급일이 구간 안이면 ③ 재판정
승인권자                    ④ CEO/이사회  또는  ④ 평시 승인권자 (③ 판정 결과로 갈림)
```

- ③에서 상신하면 결재선이 CEO/이사회면 `APR_1_CEO`, 아니면 `APR_2_Normal`로 연결됩니다.
- 각 제출 버튼은 그 사용자의 대기 화면으로, 대기 화면의 「다음 내 차례」는 다음 업무 화면으로 이어집니다.

## 3. 파일 형식과 이식 방법

화면은 Claude 디자인 캔버스의 Design Component(`.dc.html`) 형식입니다. 이 형식은 캔버스 런타임(`support.js`)이 그려 주므로
**묶음만으로는 브라우저에서 바로 실행되지 않습니다.** 마크업과 로직은 표준 HTML·JS라서 React 등으로 기계적으로 옮길 수 있습니다.

| `.dc.html` | React로 옮길 때 |
|---|---|
| `<x-dc>` 안의 마크업 | 컴포넌트의 JSX |
| `{{a.b}}` (점 경로 조회) | `{a.b}` — `renderVals()`가 돌려준 값 |
| `<sc-for list="{{rows}}" as="r">…</sc-for>` | `{rows.map((r) => …)}` |
| `<sc-if value="{{cond}}">…</sc-if>` | `{cond && …}` |
| `onClick="{{fn}}"`, `onChange="{{fn}}"` | `onClick={fn}`, `onChange={fn}` |
| `style="…"` 인라인 | `style={{…}}` 객체 또는 CSS 클래스 |
| `class Component extends DCLogic` + `renderVals()` | `React.Component` — `state`·`setState`는 그대로, `render()`에서 `renderVals()` 결과로 JSX 반환 |
| `<helmet>` | 전역 폰트(IBM Plex Sans KR) · `body{margin:0}` |

이식할 때 같이 바꿔야 할 것

1. **화면 간 상태 공유**: 지금은 화면마다 상태가 따로라 앞 단계 결과를 「모의 · 예시」 값으로 넣어 두었습니다. 실제 시스템에서는 기안 ID 기준으로 서버에서 읽어 옵니다.
2. **예시 전환 버튼 제거**: 각 화면 상단의 「모의 · 예시 전환」(결재선 예시, 받은 승인 등)과 대기 화면의 「다음 단계 진행 (모의)」 버튼은 시연용입니다.
3. **내장 데이터 → API**: 각 화면 스크립트의 `this.D`, `this.SKU`, `this.F` 등 상수는 `data/` 파일과 같은 값입니다. 원본 시스템 조회로 바꿉니다.
4. **제출·결정 버튼**: 지금은 상태만 바꿉니다. 저장, 다음 담당자 알림, 이벤트 기록을 붙입니다.

## 5. 데이터 (`data/`)

원본은 PwC 케이스 데이터룸(`04_원본데이터`)입니다. 화면 스크립트에 같은 값이 내장돼 있습니다.

| 파일 | 내용 | 원본 |
|---|---|---|
| `campaign_influencer_plan.json` | `C` 캠페인 25건, `I` 인플루언서 10명, `P` 기안 25건 | `m_campaign_ms`, `m_influencer_ms`, `mkt_budget_plan_ms` |
| `campaign_attributed_share.json` | 캠페인별 attributed GMV 비중·광고비 비중·명목 ROAS 순위 | `mkt_orders_ms`, `mkt_ad_spend_ms` (표본) |
| `influencer_attributed_share.json` | 인플루언서별 같은 지표 | 같음 |
| `contribution_profit.json` | 캠페인·인플루언서별 공헌이익·실질 ROAS·반품률·순위 | `calculation_definitions` 1.4·1.7 + 주문·반품·광고비·원가 |
| `sku_inventory_po.json` | SKU별 현재고·이동 중·4주 평균·안전재고·MOQ·리드타임·기존 발주 | `sku_inventory_ms`, `sku_weekly_sales_ms`, `m_sku_ms`, `sc_purchase_orders_ms` |
| `campaign_media_mix.json` | 캠페인별 매체 지출 구성(인플루언서·퍼포먼스·오프라인 %) | `mkt_ad_spend_ms` |
| `cash_events_forecast.json` | 6/30 종가, 회수·지급·발주 대금 이벤트, 공식 전망 | `fin_cash_daily_ms`, `fin_ar_aging_ms`, `fin_ap_aging_ms`(po_id=NONE), `sc_purchase_orders_ms`, `fin_cash_forecast_ms` |

## 6. 가동 전 확정할 가정

화면에 「가정」·「계산」·「모의」·「보완」으로 표시된 항목입니다.

| 항목 | 지금 값 | 확정 주체 |
|---|---|---|
| 새 발주 지급예정일 | 요청값 입력 → ⑥ 회신으로 확정 (원본에 규칙 없음, 기존 14건은 7/21) | SCM · 재무 |
| 제안 발주 목표 수량 | (4주 평균 + 증가 수요) × 안전재고 상한 6주 | SCM |
| 신규 발주 단가 | 기존 발주 금액 ÷ 수량 | SCM |
| 품절 예상 계산 | 일별 현재고 − 판매 + 입고, 도착일 모르는 이동 중 재고 제외 | SCM |
| 공헌이익 | GMV(쿠폰 반영 후) − 반품환불 − 원가 − 마케팅비 − 수수료 − 배송·반품물류비 (쿠폰·환불 이중 차감 안 함) | 재무 |
| 하회 구간 시나리오 | 연체 매출채권 회수/미회수 × 연체 매입채무 지급/미지급 4개, 기본은 합집합 | 재무 |
| 회신 기한 | 발주 후 3영업일 | SCM · Corevia |
| 결재자 ≠ 기안자 | 마케팅팀 전결 시 내부통제 | 내부통제 |
| SKU 수요 가정 · 이벤트 이력 · 입고예정일 필드 | 원본에 없어 보완 데이터로 추가 | 각 부서 |
