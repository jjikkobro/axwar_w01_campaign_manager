# Aurora SCM · 캠페인부터 발주까지 연결하는 의사결정 지원 앱

## 결과물 복기와 제출 데모

- [결과물 복기글 · LinkedIn](https://lnkd.in/p/gNW-jUe5)
- [제출 데모 영상 · YouTube](https://youtu.be/LShSIXkVGXg)

> 재고와 현금은 프로그램이 계산하고, AI는 근거가 있는 검토 초안을 쓰며, 신청·승인·발주는 사람이 결정합니다.

AX 인재전쟁 삼일PwC 과제를 바탕으로 만든 포트폴리오 프로젝트입니다. 가상기업 **Masil Commerce** 자료를 바탕으로 만든 테스트 앱입니다. 마케팅의 캠페인 신청부터 SCM 추가 발주, 재무의 현금·결재선 검토, 사람 승인, 모의 발주·공급처 회신, 일정 정리까지 **하나의 기안**으로 연결합니다.

중점은 화면별 자동화보다 **다른 부서의 제약을 앞 단계에서 확인해 반려와 재작업을 줄이는 것**입니다. 마케팅이 신청할 때부터 재고·입고·현금 전망을 확인하고, 일정이나 지급일을 바꾸면 이후 판단도 다시 계산합니다.

이 저장소는 포트폴리오 보관을 위해 구현 코드, 과제 가상기업 데이터, 업무 조건, 상세 설명과 검증 자료를 함께 공개합니다. 실제 기업의 운영 자료가 아니며 API 키·개인 기록 설정·로컬 DB는 포함하지 않습니다.


사용자의 최종 공개 범위에 따라 **이미지·PDF와 고객별 재구매 CSV 한 파일은 제외**했습니다. 코드·설계 설명·텍스트 검증 결과와 나머지 가상기업 자료는 포함합니다. 화면의 구현 결과는 `web/` 소스와 텍스트 검증 기록으로 확인할 수 있습니다. [공개 범위 안내](docs/submission/PUBLICATION_SCOPE.md)를 참고하세요.

## 테스트 버전과 실제 배포 버전의 차이

이 저장소는 Python 서버와 PostgreSQL을 사용하는 앱 소스입니다. GitHub에 코드를 올리는 것만으로 앱이 실행되지는 않습니다. 별도의 GitHub Pages용 체험판은 구현하지 않았습니다.

| 항목 | 로컬 테스트 버전 | AXhub 배포 구성 |
|---|---|---|
| 화면·재고/현금 계산·결재선 판정 | 같은 소스 사용 | 같은 소스 사용 |
| 실행 | Python 서버를 직접 실행 | Docker로 서버 실행 |
| 접속 | 기본값은 로컬 주소에서만 접속 | `PUBLIC_ACCESS=true`, 누구나 로그인 없이 접속 |
| 저장 | 직접 준비한 PostgreSQL | AXhub PostgreSQL, `DATABASE_URL` 주입 |
| GPT 검토 초안 | 본인 키 설정 시 사용, 키 없이도 업무 계산 가능 | AXhub 보안 환경변수의 `AI_API_KEY` 사용 |
| GPT 키 관리 | 서버 환경변수 또는 로컬 전용 설정 | `AI_SETTINGS_BACKEND=environment`; 앱 화면에서 키 변경·삭제 불가 |
| 작업 기록 | 연결한 로컬 DB에 저장 | 연결한 배포 DB에 저장; 로컬 기록 자동 이전 없음 |
| 승인·발주·회수·공급처 회신 | 시연용 입력 | 배포에서도 시연용 입력 |

**배포는 실서비스 전환을 뜻하지 않습니다.** 개인별 로그인·부서 권한 인증, 은행·공급처 실제 연동은 후속 설계입니다. 역할 선택은 시연 기능이며 실제 사용자 권한을 증명하지 않습니다. 이 표는 저장소의 배포 구성을 설명하며 현재 운영 URL의 가동 상태를 보증하지 않습니다.

[제출 설계 설명 7개 문항](docs/submission/DESIGN_EXPLANATION.md)과 [포트폴리오 읽기 안내](docs/submission/PORTFOLIO_MAP.md)에서 판단 근거·구현 코드·검증 기록을 연결해 볼 수 있습니다. `01_참가자_배포용/`는 대회 제공 문제·가상기업 원본 자료이며 참가자가 작성한 코드·추가 설계와 구분합니다. 원본 자료는 데이터 추출과 일부 실행 기능의 출처 확인을 위해 함께 보존했습니다. 사용자 요청으로 본 앱에서 사용하지 않는 고객별 재구매 CSV 한 파일은 제외하고 [자료 출처·구성 개요](docs/submission/DATA_PROVENANCE.md)만 남겼습니다.

## 무엇을 해결하려 했나

### 1. 재무에서 뒤늦게 발견하던 현금 제약을 기획 단계로 이동

캠페인 → 증가 수요 → 추가 발주 → 지급일 → 일별 현금 전망 → 30억 원 하회 구간 → 결재선으로 연결합니다. 전망 기간 밖의 일정이나 미확인 지급일을 임의로 채우지 않고 신청·상신을 차단하고 확인 작업으로 남깁니다.

제공 자료를 이용한 시연에서는 같은 발주라도 지급일이 **9/21이면 SCM 전결**, **7/21이면 CEO·이사회** 대상이 됩니다. 미확인 미수금·미지급금은 네 가지 현금 시나리오로 계산하며, 회수 확인을 기록하면 결재선을 재판정합니다. 이는 과제 자료 기준의 예시이며 현재 기업의 예측값이 아닙니다.

### 2. 다른 부서에 미치는 영향을 같은 기안에서 확인

마케팅은 기간·SKU·주당 증가 수요·예산을 입력하고, SCM은 최근 완료 4주 판매·재고·기존 발주·최소 주문 수량·리드타임으로 추가 발주안을 검토합니다. 재무는 현금 전망과 승인 경로를 확인합니다.

반려하면 보완 작업을 만들고 같은 기안의 수정 버전으로 재신청합니다. 조건부 승인은 조건 작업과 발주 차단으로 이어지며, 사람의 재승인이 필요합니다. 공급처 회신이 승인 당시 조건과 달라지면 재무 재검토로 연결합니다. 캠페인 집행 승인과 상품 발주 승인은 별도로 다룹니다.

### 3. AI 설명과 사람의 결정을 분리

GPT에는 기안·부서 의견·시스템 계산값·출처 자료를 전달해 요약, 위험, 대안, 확인 질문과 근거의 초안을 요청합니다. AI 응답은 검토가 필요한 초안이며, 초안 생성 자체가 승인·발주·상태 변경으로 이어지지 않습니다.

기안 신청, SCM 인계, 재무 상신, 승인·반려, 발주 전달, 회신 기록, 산식 적용과 자료 저장은 담당자의 명시적 행동으로 처리합니다.

### 4. 원본·가정·계산을 구분

자료와 화면에서 **원본 사실 / 부서 주장 / 참가자 가정 / 내부 통제 / 계산 결과 / 모의 회신**을 구분합니다. 공식 현금 전망은 부서 주장으로 재계산과 나란히 비교하고, 마감 기준이 미확인인 차이 원인은 추정으로 표시합니다.

현금 계산은 6/30 잔액에 미수금, 발주에 연결되지 않은 미지급금, 발주 지급을 반영합니다. 발주에 연결된 미지급금을 다시 차감하지 않고, 표본 캠페인의 비용을 전사 현금에 합산하지 않습니다. 미래 증가 수요는 과거 사례를 참고한 가정이며 비교 이력이 부족하면 직접 입력을 요청합니다.

## 실행

Python 3.14와 PostgreSQL이 필요합니다. 아래 명령은 직접 준비한 개발용 DB를 사용합니다. `scripts.seed`는 기존 자료를 덮어쓰지 않고 없는 초기 자료를 추가합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 실제 접속정보는 로컬 환경에만 설정합니다.
read -rsp '개발 DB 연결 URL: ' DATABASE_URL; echo
export DATABASE_URL
python -m scripts.migrate
python -m scripts.seed
python -m app.server
```

브라우저에서 <http://127.0.0.1:8080>을 엽니다. PostgreSQL 없이 HTML 파일만 열면 업무 계산과 저장을 사용할 수 없습니다.

GPT를 사용하려면 서버를 실행할 터미널에서 다음과 같이 설정한 뒤 서버를 시작합니다. 키가 없으면 AI 초안 기능을 사용할 수 없으며 재고·현금 계산은 키 없이 동작합니다.

```bash
export AI_SETTINGS_BACKEND=environment
read -rsp 'OpenAI API 키: ' AI_API_KEY; echo
export AI_API_KEY
export AI_MODEL=gpt-5-mini
```

AXhub에서는 `axhub.yaml`과 `Dockerfile`을 사용합니다. `AI_API_KEY`, `SESSION_SECRET`은 보안 환경변수에 등록하고, `PUBLIC_ACCESS=true`로 설정합니다. 키나 DB 접속정보를 코드·README에 입력하지 않습니다. 저장 데이터는 AXhub DB에 둡니다.

## 따라 해 보기

1. 마케팅 역할에서 캠페인 기간·상품·증가 수요·예산을 입력하고 재고·현금 근거를 확인합니다.
2. SCM 역할에서 추가 발주 수량·입고일·지급일을 검토하고 재무에 인계합니다.
3. 재무 역할에서 네 가지 현금 시나리오와 결재선을 확인하고 상신합니다.
4. 승인권자 역할에서 승인·조건부 승인·반려를 기록하고 후속 작업을 확인합니다.
5. 승인한 범위의 모의 발주·공급처 회신을 기록한 뒤 재고와 일정 변화를 확인합니다.

조건 변경 사례로 지급일 9/21 ↔ 7/21을 비교하고, 지급일 누락 차단·조건부 승인 후 발주 차단·반려 후 재신청을 확인할 수 있습니다. 기존 검증 기록은 [시나리오 결과](docs/verification/system/SCENARIO_RESULTS.json)에 있습니다. 이는 기록 당시의 결과이며 현재 실행 결과와 구분합니다.

## 개발에서 중점으로 삼은 부분

AX 컨설팅 관점에서 부서 간 판단의 연결과 업무 왕복 감소를 우선했습니다. 제출 설명에 담은 유사 기업 조사·현업 인터뷰, 마케팅 자동화 도구와 AI 채용·이력서 분석 개발 경험을 바탕으로, 불필요한 업무는 앞 단계에서 걸러내고 AI 답변의 근거와 사람의 결정을 분리하도록 설계했습니다.

코드 구현에는 AI 코딩 도구를 활용했습니다. 업무 범위·원본 보존·승인 책임을 정하고, 역할별 화면을 원본 자료와 대조하며 실제 담당자처럼 검토·수정하는 데 중점을 뒀습니다. 이 저장소의 Masil Commerce 자료는 과제의 가상기업 데이터입니다.

## 공개 시 제외하는 정보

API 키·DB 접속정보·세션 비밀값, 개인 기록 키가 들어 있는 `.agents/`, `.codex/`, `.claude/`, 로컬 설정·DB가 있는 `.axhub/`는 공개 대상에서 제외합니다. 테스트에 쓰인 `sk-test-*`, `sk-unit-test` 등은 실제 서비스 키가 아닌 모의 값입니다. 소스와 테스트에서 환경변수 이름을 사용하는 것은 키 값 공개와 다릅니다.
